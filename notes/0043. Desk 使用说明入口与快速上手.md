## 打开或创建知识库

已有知识库时，用 Desk 打开含有 `tnotes.json` 的目录；也可以打开集中存放多个知识库的父目录。Desk 会识别知识库并显示目录。普通 Markdown 文件夹不等同于已经初始化的 TNotes 知识库。

新建知识库时，填写文件夹名和显示名称。文件夹名使用英文字母、数字、点、下划线或连字符，长度为 1–100；显示名称可以写中文。目标文件夹必须尚不存在。

最小知识库包含：

```text
TNotes.demo/
├── tnotes.json
├── TOC.md
├── notes/
│   └── 0001. 开始使用.md
├── .gitignore
└── .gitattributes
```

首次添加附件时会使用库级 `assets/`。`package.json`、GitHub Pages 工作流、根 README、Git 初始化均为可选项。只在 Desk 中写笔记、使用内嵌站点预览，不必先在知识库执行 `pnpm install`。

## 创建、整理和编辑笔记

1. 在目录侧栏创建笔记或分组。笔记写入 `notes/NNNN. 标题.md`；分组只是 `TOC.md` 中的结构，不创建笔记子文件夹。
2. 修改标题时使用 Desk 的重命名功能。四位编号是稳定编号，不要为了重新排序而改编号。
3. 拖动目录项调整顺序和层级；完成勾选写回 `TOC.md`。
4. 打开笔记，选择可视化、源码或只读视图。
5. 保存后，正文仍是可以用其他编辑器打开的 Markdown 文件。

笔记标题来自文件名；新笔记保留同名 H1，正文从 H2 开始分节。笔记名改变时优先让 Desk 同步处理，不要另外用 frontmatter `title` 维护第二份标题。

### 三种笔记视图与站点预览

| 入口 | 用途 |
| --- | --- |
| 可视化编辑 | 直接编辑段落、列表、表格等；扩展块可能通过块工具或源码小编辑器修改 |
| 源码视图 | 编辑 Markdown、容器、组件标签、frontmatter |
| 只读视图 | 阅读当前笔记，避免直接修改 |
| 知识库站点预览 | 用 SSG 查看接近发布站点的结果，检查导航与扩展渲染 |

可视化编辑与发布站点使用的处理流程不同。自定义 Vue、复杂 HTML 等内容，以站点预览为发布效果依据。遇到无法安全切换视图或内容无法保真时，先保留当前修改，再用源码方式处理。

## 保存、同步和发布是三个步骤

- **保存**：把修改写入本地 Markdown。自动保存默认开启，停止编辑约 1 秒后保存；也可手动保存。
- **Git 同步**：在变更面板检查差异，提交并推送到配置的远端；需要正常可用的 Git 和认证。
- **发布**：有 Pages 工作流的知识库，在推送触发并完成部署后，线上站点才更新。站点预览不等于已发布。

可为单个知识库开启空闲后自动提交推送。它默认关闭，也不能替代处理冲突或配置 Git 凭据。

## 图片、附件和自由绘图

- 默认把粘贴的图片保存到当前库 `assets/`，笔记中引用 `../assets/文件名`。
- 本地图片按笔记四位编号归属。同一笔记中相同内容的图片可能复用已有文件；不同笔记分别保存自己的附件。
- 选中图片可调整描述、宽度和对齐；图片说明与 Markdown 的 alt 文本对应。
- 笔记工具栏可打开“本笔记资源”；知识库的“资源”入口可查看引用、断链、闲置候选与重复资源。
- 资源重命名、移入回收区、合并、压缩先生成可检查的计划。未知动态引用、未保存编辑或过期计划可能阻止执行。
- 图片压缩当前使用 sharp，有损；GIF 不自动转视频，SVG 和画布原始文件不作为普通位图覆盖。
- `/ex` 创建 Excalidraw 画布。保留 `.excalidraw` 原始文件和同名 `.svg` 展示文件，笔记引用 SVG；点击相应编辑入口继续画图。

资源回收区、临时恢复信息保存在 Desk 应用数据中，不会随知识库 Git 自动同步。Git 历史面板中的恢复与资源整理的撤销不是同一功能。

## 历史和恢复

历史面板可查看笔记及其归属附件的 Git 版本、比较差异，并在确认恢复计划后恢复。恢复以真实 Git 历史为依据；尚未提交的内容不会自动成为 Git 历史版本。

若 Desk 提示待恢复草稿、未完成事务或磁盘内容发生变化，先按提示处理。不要用直接覆盖磁盘文件的办法代替恢复流程。
