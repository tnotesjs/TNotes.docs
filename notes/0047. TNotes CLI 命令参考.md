# TNotes CLI 命令参考

> 核对基线：2026-09-15，TNotes Desk 0.8.2 所在源码版本。本文是供后续人工完善的使用说明初稿；已发布旧版本可能与此不同。

## 适用范围

Desk 日常编辑不要求运行这些命令。CLI 用于终端维护、批量建库或 CI 构建。当前对用户提供的是 `tnotes-kb` 和 `tnotes-ssg`，不是旧 `tnotes --xxx`。

以下以已经安装相应依赖的知识库目录为工作目录，使用 `pnpm exec` 调用本地二进制。`tn:*` 只是 `package.json` 中的脚本别名，只有该库声明了脚本才能运行。

```bash
pnpm exec tnotes-kb --help
```

**`tnotes-ssg --help` 当前没有实现**，会报未知命令。SSG 的完整命令列表就是本文列出的 `dev`、`build`、`preview`。

## tnotes-kb：全部命令

### 帮助

```bash
pnpm exec tnotes-kb --help
pnpm exec tnotes-kb -h
```

不带任何参数也会打印帮助，但当前退出码为 1；自动化脚本检查帮助时使用显式 `--help`。帮助开关只在第一个参数位置识别：`init --help` 不是子命令帮助；**不要用 `update --help` 试探帮助，它可能实际更新当前目录的统计文件**。

### init：创建知识库

```bash
pnpm exec tnotes-kb init TNotes.demo --title "示例知识库" --parent ../kbs
```

| 参数 | 必填 | 默认 / 作用 |
| --- | --- | --- |
| `<文件夹名>` | 是 | 英文字母、数字、点、下划线或连字符，1–100 字符；目标目录须不存在 |
| `--title <显示名称>` | 否 | 默认使用文件夹名 |
| `--parent <父目录>` | 否 | 默认当前工作目录 |
| `--package-json` | 否 | 写入构建所需 package.json 及配套工程配置 |
| `--github-pages` | 否 | 写入 Pages 工作流，同时启用 package.json |
| `--readme` | 否 | 写入根 README |
| `--git-init` | 否 | 在新目录初始化 Git |

全部可选开关默认关闭；基础文件仍会写入，包括 `tnotes.json`、`TOC.md`、首篇笔记、`.gitignore`、`.gitattributes`。

```bash
pnpm exec tnotes-kb init TNotes.demo \
  --title "示例知识库" \
  --parent ../kbs \
  --github-pages \
  --readme \
  --git-init
```

这只创建本地文件及可选 Git 仓库，不会自动创建 GitHub 仓库、配置远端或启用 GitHub Pages。CLI 初始化没有 `--force` 覆盖已有目录的选项。

`--title`、`--parent` 必须用空格分隔值，不支持 `--title=名称` 等形式；它们直接消费下一个参数，务必提供值，避免把后续开关误当作值。未知开关和多余位置参数会报错。

**当前 Pages 脚手架还需要补一步配置**：生成的新库只默认写 `name/title`，但工作流会无条件执行 `pnpm tn:update`。首次部署前，在 `tnotes.json` 开启 `"stats": { "enabled": true }` 并保留 TOC 的 Git 历史；不需要统计时，手动删除工作流中的 Update stats 步骤。否则构建会停在“完成趋势统计未开启”。

### update：回填完成趋势

```bash
pnpm exec tnotes-kb update
pnpm exec tnotes-kb update ../TNotes.demo
```

目录可省略，默认当前目录。命令读取 Git 中 `TOC.md` 的历史完成状态，更新 `tnotes.json` 的 `stats.completedNotesCount`。

当前参数解析比较宽松：取 `update` 后第一个不以 `--` 开头的参数作为目录，跳过双横线开关，其余参数忽略；单横线参数（如 `-h`）还可能被当作目录。它没有可用的子命令选项，不要追加帮助或其他试探参数，也不要把“没报未知选项”理解为参数生效。

前提是知识库启用 `stats.enabled`，且有可读取的 Git 历史。关闭统计时会报“完成趋势统计未开启”，不执行回填。它不重新生成笔记正文、重排编号或同步旧 core 文件。

## tnotes-ssg：全部命令

| 命令 | 用途 | 目录参数 |
| --- | --- | --- |
| `tnotes-ssg dev [目录]` | 启动开发预览，监听内容变化 | 默认当前目录 |
| `tnotes-ssg build [目录]` | 构建静态站点到 `.tnotes/dist` | 默认当前目录 |
| `tnotes-ssg preview [目录]` | 预览已经构建的静态产物 | 默认当前目录 |
| `tnotes-ssg` | 等同当前目录的 `dev` | 不能用裸路径代替 `dev [目录]` |

```bash
pnpm exec tnotes-ssg dev
pnpm exec tnotes-ssg build
pnpm exec tnotes-ssg preview

pnpm exec tnotes-ssg build ../TNotes.demo
```

`preview` 前先运行 `build`。修改笔记后，静态预览不会自动重新构建。

CLI 当前只读取“命令 + 目录”这两个位置参数，不提供 `--port`、`--host`、`--outDir`、`--config`、`--help`、`--version` 选项。不要照搬 Vite CLI 的参数；端口、base、语言和 Markdown 开关写在 `tnotes.json`。

未知选项并不总会显式报错：`build --port 9000` 会把 `--port` 当目录；`build . --port 9000` 则使用 `.` 并忽略后面的参数。没有报错不能证明端口覆盖成功。

默认端口为 9193，监听本机 `127.0.0.1`；端口占用时可能选择后续可用端口，以终端打印的地址为准。`base` 会影响访问路径。

## 知识库的常见脚本别名

```json
{
  "scripts": {
    "tn:update": "tnotes-kb update",
    "tn:build": "tnotes-ssg build",
    "tn:dev": "tnotes-ssg dev",
    "tn:preview": "tnotes-ssg preview"
  }
}
```

对应 `pnpm tn:update`、`pnpm tn:build`、`pnpm tn:dev`、`pnpm tn:preview`。这是库的工程约定，不是 Desk 自动要求每个库都安装的依赖。

`pnpm build`、`pnpm --filter desk dev` 等是 TNotes 源码仓库的开发命令，不应作为普通知识库的日常命令介绍。

## Git 同步与 Pages

Git 命令属于 Git，可通过 Desk 界面使用，也可在终端执行。例如先查看状态与差异，再按需要提交指定文件和推送：

```bash
git status
git diff
git add notes/ TOC.md
git commit -m "docs: 更新笔记"
git push
```

如果修改了附件或配置，还需把相应文件纳入提交。推送成功并不代表 Pages 已完成；继续检查该知识库的 Actions 部署结果。

当前脚手架的子库部署会向 `tnotesjs/TNotes.root` 发送收集通知；关联工作流需要可访问根仓库的 `TNOTES_DISPATCH_TOKEN`。这不是 `tnotes.json` 字段，也不是 Desk 图床 Token。已安装的旧 npm 版本可能仍生成旧根库地址，应检查生成的工作流。

## 旧命令迁移

| 历史写法 | 当前处理 |
| --- | --- |
| `tnotes --dev` / `--build` / `--preview` | 使用 `tnotes-ssg dev/build/preview` |
| `tnotes --create-notes` | 在 Desk 创建笔记；`tnotes-kb init` 创建的是知识库 |
| `tnotes --update` | 使用 `tnotes-kb update`，语义已缩小为统计回填 |
| `tnotes --update-completed-count` | 合并到 `tnotes-kb update` |
| `tnotes --pull` / `--push` / `--sync` 与 `*All` | 使用 Desk 的 Git 操作或原生 Git；无相同 CLI 子命令 |
| `tnotes --sync-scripts` | 停用；工程依赖通过包管理器维护 |
| `tnotes --fix-timestamps` | 无当前替代命令 |
| `tnotes --help` | 旧工具帮助；当前 KB 帮助为 `tnotes-kb --help` |

当前源码没有提供一个面向用户的 `desk build` / `desk --help` 无头 CLI；不要把架构计划中的目标当作已经发布的命令。
