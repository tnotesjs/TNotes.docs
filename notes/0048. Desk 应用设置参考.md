# Desk 应用设置参考

## 配置在哪里

在 Desk 打开“设置”，可通过外观、标签、目录、图片、工具和配置文件等页面修改。配置保存在应用用户数据目录的 `.tn-desk-config.json`，不是知识库根目录中的文件。

“配置文件”页支持保存并校验、导出、导入和恢复默认。手写配置使用标准 JSON，不能加注释。必须区分两个入口：

- **界面保存、配置页保存和导入**：严格校验；非法 JSON 或非法字段会报错，不会因为校验失败而用默认值覆盖原文件。
- **读取已在磁盘上的配置**：对非法字段尝试逐项回退默认值、保留合法字段；检测到被丢弃字段时尝试备份为 `.tn-desk-config.json.invalid.bak`。文件无法读取或 JSON 无法解析时使用默认值，不能保证这一路也会生成备份。

普通配置也可能包含个人路径和图床仓库信息，修改前先导出，分享前检查。未知全局字段不会成为有效设置，重新序列化时可能被丢弃。

全局配置只控制当前设备的 Desk。需要随知识库共享的选项写入 `tnotes.json`，见 [知识库配置](./0049.%20知识库与笔记配置参考.md)。它不会把 Desk 的主题、标签页或图床 Token 变成发布站点的配置。

## 外观与编辑

| 字段 | 默认值 | 允许值与作用 |
| --- | --- | --- |
| `version` | `1` | 配置格式版本，保持为 1 |
| `theme` | `"system"` | `system/light/dark`，跟随系统、浅色、深色 |
| `density` | `"comfortable"` | `comfortable/compact`，界面密度 |
| `defaultNoteView` | `"visual"` | `visual/readonly/source`，笔记默认视图 |
| `defaultNotePageWidth` | `"standard"` | `standard/wide`，笔记默认页宽 |
| `noteTocDisplay` | `"expanded"` | `hidden/collapsed/expanded`，笔记内目录显示状态 |
| `headingNumberMaxDepth` | `2` | 1–6 层，标题编号最大深度；应用层数值会取整并限制范围 |
| `appZoomPercent` | `100` | 50–200，整个应用缩放比例；快捷键每次调 10 |
| `autosave.enabled` | `true` | 是否自动保存 |
| `autosave.delayMs` | `1000` | 整数 250–30000，自动保存延迟，单位毫秒 |
| `createNotePosition` | `"top"` | `top/end`，新笔记默认放在对应列表顶部或末尾 |
| `workspaceLayout` | `"kb-dir-content"` | `kb-dir-content/content-dir-kb`，三栏从左到右的排列 |
| `prettier` | `false` | 源码视图保存时是否使用 Prettier |

`prettier` 仅在源码视图保存时生效，可视化编辑不会因此整篇重排。使用 Prettier 内置默认风格，不读取库里的 `.prettierrc`。库级 `prettier` 优先于全局值，库级未设置时才跟随全局。

`headingNumberMaxDepth` 也可以被库级同名值覆盖。改变上限不等于立即重写全部笔记；需要在笔记中执行标题编号操作。

## 标签页

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `tabs.maxOpenCount` | `10` | 最大打开数量设置，整数 1–30 |
| `tabs.wrap` | `true` | 标签栏是否允许换行 |
| `tabs.autoRevealInToc` | `true` | 切换笔记时自动在目录定位 |

预览标签、保持打开、固定标签是不同状态。标签关闭与保留还受未保存修改、固定状态等规则影响，不应把数量上限理解为直接丢弃未保存内容。

## 目录显示

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `toc.showNoteIndex` | `true` | 显示四位笔记编号 |
| `toc.showNoteStatus` | `true` | 显示笔记完成状态 |
| `toc.doneEmoji` | `"✅"` | 已完成状态标记 |
| `toc.undoneEmoji` | `"⏰"` | 未完成状态标记 |
| `toc.changesCollapsedByDefault` | `true` | 变更分区默认折叠 |

这些选项只改变 Desk 展示。隐藏完成标记不会删除 `TOC.md` 的复选框，也不会改变完成态。

## 工具与 Git

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `ide` | `"vscode"` | `vscode/cursor`，从 Desk 打开外部编辑器 |
| `gitPath` | `null` | 使用自动查找的 Git；也可指定非空可执行文件路径 |
| `nodePath` | `null` | 使用自动查找的 Node；也可指定非空可执行文件路径 |
| `confirmBeforeCommit` | `false` | 提交前是否先确认 |

仓库地址和 Git 认证不是这里的路径字段。单库自动推送配置写在 `tnotes.json.autoPush`，没有全局同名开关。

## 图片上传与 GitHub 图床

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `imageUpload.defaultTarget` | `"local"` | `local/github`，默认写入本地库或 GitHub 图床 |
| `imageUpload.github.repository` | `""` | 图床仓库，如 `owner/images`，也支持可识别的 GitHub 仓库 URL |
| `imageUpload.github.branch` | `"main"` | 上传目标分支，非空 |
| `imageUpload.github.path` | `"/"` | 仓库内目标目录，例如 `assets/` |
| `imageUpload.github.cdnTemplate` | 见下文 | 发布后引用图片的地址模板 |
| `imageUpload.github.fileNameFormat` | `${YY}-${MM}-${DD}-${HH}-${mm}-${ss}` | 图床文件名格式 |

默认 CDN 模板：

```text
https://cdn.jsdelivr.net/gh/${username}/${repository}@${branch}/${filepath}
```

CDN 模板变量：

| 变量 | 含义 |
| --- | --- |
| `${username}` | 仓库所属用户或组织 |
| `${repository}` | 仓库名，不含所属用户 |
| `${branch}` | 分支 |
| `${filepath}` | 仓库内文件完整相对路径 |

文件名格式支持 `${YYYY}`、`${YY}`、`${MM}`、`${DD}`、`${HH}`、`${mm}`、`${ss}`；区分月份 `MM` 和分钟 `mm`。文件扩展名按上传文件补齐，同名冲突会尝试添加后缀。

底层文件命名还识别 `${index}`，但它依赖调用方提供笔记编号；当前 GitHub 图床上传不传该编号，不能靠它生成图床笔记前缀。本地笔记图片由 Desk 的本地资源流程单独附加编号，不受图床文件名设置控制。

### Token

在图片设置页单独填写、测试并保存 GitHub Token。Token 不放入 `.tn-desk-config.json`，也不放入 `tnotes.json`；通过系统安全存储相关能力独立处理。界面提示“留空不会修改现有 Token”，移除需使用对应操作。导出普通配置不能当作 Token 备份。

仅把默认目标改为 `github` 并不等于图床已可用，还需要仓库、分支、Token 的配置有效。图床 Token 与 Git 推送认证、Pages 通知根库的 Token 是三件事。

## 图片优化默认值

| 字段 | 默认值 | 允许值与状态 |
| --- | --- | --- |
| `imageUpload.optimize.encoder` | `"sharp"` | 配置兼容 `sharp/oxipng`，当前实际接入的是 sharp |
| `imageUpload.optimize.strength` | `"medium"` | `low/medium/high`，对应更轻/默认/更强压缩 |
| `imageUpload.optimize.outputFormat` | `"keep"` | `keep/webp/jpeg`，保留格式或输出指定格式 |
| `imageUpload.optimize.maxDimension` | `null` | 历史兼容字段；读取时固定归一为 null，当前不提供按最大边缩放 |

sharp 强度对应质量 90 / 80 / 60。优化可能有损，要通过对比预览判断是否接受；`keep` 表示保留格式，不表示无损。

旧 `quality` 和 `oxipngLevel` 读取时会迁移到 `strength`，新配置不再写它们。`oxipng` 虽在配置兼容枚举里，但不能据此认定其编码器已可用。

这些是相关上传/优化操作的默认参数，不会因为改动设置就批量重写整个知识库的已有图片。

## 更新和隐藏知识库

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `updates.autoCheck` | `true` | 自动检查 Desk 新版本；检查不等于自动下载安装 |
| `hiddenKnowledgeBases` | `[]` | 隐藏知识库的标识列表 |
| `knowledgeBases` | `{}` | 按知识库标识保存的本机覆盖项 |
| `knowledgeBases.<库标识>.hidden` | 未设置 | 兼容的单库隐藏字段 |

隐藏状态由界面管理更稳妥，不建议凭目录显示名猜测内部标识。隐藏不会删除知识库文件。

## 可复制的最小配置示例

```json
{
  "version": 1,
  "theme": "system",
  "defaultNoteView": "visual",
  "autosave": {
    "enabled": true,
    "delayMs": 1000
  },
  "prettier": false,
  "tabs": {
    "maxOpenCount": 10,
    "wrap": true,
    "autoRevealInToc": true
  }
}
```

这是配置结构示例。导入或整份替换时，未提供的字段可能回默认值；若只是调整一项，优先使用设置页对应控件。
